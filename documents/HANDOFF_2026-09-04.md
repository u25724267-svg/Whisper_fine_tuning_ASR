   frozen manifests changes their hashes and weakens reproducibility.

## 2. Research objective

This project investigates limited-resource Shona ASR using OpenAI Whisper.
Curriculum learning is the main thesis contribution.

### Research questions

- **RQ1:** Do static or dynamic acoustic curricula improve limited-data Shona
  Whisper fine-tuning?
- **RQ2:** Does the selected curriculum interact beneficially with synthetic
  waveform augmentation for clean and out-of-distribution generalization?
- **RQ3:** Does the Shona-selected curriculum transfer to Tshivenda?
- **RQ4:** Does confidence-filtered pseudo-labeling improve over matched
  supervised training?

### Current scientific state

- RQ1 screening, replication, item evaluation, and selection are complete.
- C3 strict joint SNR-duration ordering is selected for the RQ2 curriculum
  factor.
- RQ2 A2 seed 42 is complete with hashed item-level predictions.

## 5. RQ1 implementation notes

### Static curricula

- C1: SortaGrad, duration ascending in epoch 1 and seeded random later epochs.
- C2: strict high-to-low SNR.
- C3: strict ascending difficulty using
  `0.5 * duration_percentile + 0.5 * (1 - snr_percentile)`.
- C4: cumulative C3 priority with eligible fractions 1/3, 2/3, and 1.
- C4R: mandatory random-priority pacing control with identical exposure counts.

### Dynamic curricula

- C5 uses online summed token NLL divided by audio duration.
- The name S2S-margin is historical. The score is not a hypothesis margin.
- Scores are captured during each training forward, so they are intentionally
  path-dependent rather than frozen-checkpoint scores.
- C6 uses pre-forward greedy per-item WER.
- C7 combines C3 acoustic score and S2S percentile with fixed 0.5/0.5 weights.

### Important defects already fixed

1. C4 initially failed before step 1 because concurrent sampler iterators wrote
   one temporary filename. UUID temporary names fixed the race.
2. C4 then failed because `curriculum_orders` did not exist at write time. Audit
   writers now create their parent directories.
3. RQ2 materializer initially recorded staging-directory audio paths. Workers
   now write to staging but record final promoted paths.
4. The augmented manifest initially contained a train-only `augmentation_seed`
   column, causing Hugging Face cross-split schema failure. Seed provenance now
   remains only in the parameter audit, and train/validation/test schemas match.
5. Failed 64-row staging-path test outputs were retained with
   `.broken_staging_paths` suffixes and must not be used.

## 6. RQ2 design

RQ2 is a 2x2 factorial:

| Cell | C3 curriculum | Waveform augmentation | Status |
|---|---:|---:|---|
| A0 | No | No | Reuse C0 seeds 42-44 |
| A1 | Yes | No | Reuse deterministic C3 |
| A2 | No | Yes | Seed-42 training complete |
| A3 | Yes | Yes | Seed-42 dry run passed; not launched |

SpecAugment is disabled in all primary A0-A3 cells. It is not part of the
factorial. A later SpecAugment sensitivity is allowed only if the waveform
factorial first shows a benefit.

### Frozen waveform policy

Policy name: `rq2-waveform-mild-v1`

- Asset source: OpenSLR SLR28
- License: Apache 2.0
- Point-source non-speech noise files: 843
- Simulated RIR files: 60,000
- Speed perturbation probability: 0.5
- Speed factors when applied: 0.9 or 1.1 with equal probability
- Simulated RIR probability: 0.3
- Additive noise probability: 0.5
- Target SNR: uniform 10-25 dB
- Transform order: speed, RIR, noise, anti-clipping attenuation
- Validation, test, and FLEURS audio remain unmodified
- Augmentation is materialized once per seed, not sampled online each epoch
- Per-utterance decisions derive deterministically from global seed and ID

Policy file: `configs/rq2-waveform-mild.json`  
Policy SHA-256:
`b50d74488cdc2aa9e9a5886dae21ebb23a4ab9a647bc8bc6fea326f0916e4def`

### Seed-42 materialization

- Rows: 13,807
- Speed applied: 6,976
- RIR applied: 4,216
- Noise applied: 6,983
- No transform selected: 2,370
- Anti-clipping attenuation: 1,267
- Every ID and transcript matches the clean source.
- Every output is finite mono 16 kHz FLAC.

### A3 ordering safeguard

A3 must use C3 difficulty calculated from the original clean duration and SNR
metadata. Recalculating duration ranks from speed-perturbed audio changes the
order from `86ff768edcc8` to `a36d3ab9f7c1` and confounds the factorial.

`train_snr_curriculum.py` now supports:

```json
"duration_source": "acoustic_metadata_manifest_duration"
```

A3's validated dry run reproduces the clean C3 order hash prefix
`86ff768edcc8` while loading the same augmented seed-42 manifest as A2.

### Sequence-runner scope

`scripts/run_sequence.sh` takes an explicit ordered list of experiment
directories. It preflights the entire list before launching anything, skips
complete training and prediction artifacts, waits for retained tmux panes by
pane-dead status, and stops on the first failure or incomplete output.

It does not implement missing experiments, materialize seed-specific augmented
data, create configs, run bootstrap comparisons, generate corrupted evaluation
sets, evaluate FLEURS, or make scientific decisions. An unimplemented directory
causes preflight failure before any requested stage launches.

### RQ2 primary pipeline

`scripts/run_rq2_primary.sh` is the higher-level unconditional pipeline. It uses
`run_sequence.sh` as its training/export subroutine and performs the missing
non-training stages around it:

1. Verify all fixed RQ1 and seed-42 RQ2 prerequisites.
2. Complete any missing seed-42 matched bootstrap comparisons.
3. Materialize deterministic waveform data for seed 43.
4. Generate immutable hash-pinned A2/A3 seed-43 experiment directories.
5. Dry-run A2 and A3, including the frozen C3 order check.
6. Train A2 then A3 sequentially and export item predictions.
7. Write A2-vs-C0, A3-vs-A2, and A3-vs-C3 comparisons.
8. Repeat steps 3-7 for seed 44.
9. Write a descriptive cross-seed factorial JSON and Markdown summary.
10. Stop before scientific interpretation and print the manual decision gate.

The pipeline is resumable by artifact presence and refuses partial
materializations, differing generated configs, incomplete outputs, or failed
tmux panes. It does not open FLEURS or automatically launch SpecAug, Medium,
RQ3, or RQ4 work.
